# Feature matrix (spec §20)

Every spec ID F01–F51 and X01–X04 is listed below. The status is the most conservative one that is true today.

**Status vocabulary**

| Status | Meaning |
|---|---|
| VERIFIED | Checked against real BCH mainnet data, with evidence in `evidence/` (round 4: executed on mainnet through the hosted app's live path and certified against chain) |
| TESTED | Covered by automated tests (vitest and/or Playwright). Value moves only on the LOCAL mock chain, which runs the real BCH 2026 VM |
| IMPLEMENTED | Code and UI exist and are exercised by the browser tests, but are only partly unit-tested |
| PARTIAL | Part of the feature works, as described. The missing part is listed under limitations |
| BLOCKED | Cannot be completed without something outside this repository (protocol builder, owner authorization, network access) |
| NOT STARTED | No code yet |

Tests are written as `file (n)`. Paths are relative to the repo root. UI routes are under the Studio (`apps/web`).
Snapshot (2026-11-21 IST, round 4): 35 vitest files / 149 tests, Playwright against the hosted URL (desktop + mobile, `--workers=1`): 80 passed, 1 failed (sandbox per-instance state; passes alone), 13 skipped by design.

**Counts (55 IDs):** VERIFIED 12 · TESTED 28 · IMPLEMENTED 3 · PARTIAL 7 · BLOCKED 5 · NOT STARTED 0.
VERIFIED + TESTED = 40/55 (72.7%); VERIFIED alone 12/55 (21.8%; 10/55 in round 4, 3/55 in round 3); anything working at least partly (all but BLOCKED) 50/55 (90.9%).

**Round 6 (real third-party wallet):** Cashonize v0.16.0 (https://cashonize.com, open source, `@wizardconnect/wallet`), with a fresh seed on the box, paired with the deployed app over WizardConnect and signed a mainnet flash on `fuse-live-1`: [`9df5dced…`](https://bchexplorer.cash/tx/9df5dcede4a6e3a7d14f738a0a340d9f806c2317bedb33238d081a21d6bee8d0), relayed by the hosted `/api/broadcast` with an execution authorization (`intentBound: true`), certificate VERIFIED · INTENT_BOUND. The F/X counts below are unchanged (the wallet rows are cross-cutting).
